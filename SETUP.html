مدیریت سایت، بدون دیتابیس جدا

سایت و پنل روی گیت‌هاب پیجز می‌مانند. پنل تغییرات را در مخزن خودت ذخیره می‌کند. برای ویدیوهای پروژه لینک یوتیوب می‌گذاری؛ عکس‌ها و ویدیوی کوچک هدر در گیت‌هاب ذخیره می‌شوند.

۱. یک‌بار فایل‌ها را در گیت‌هاب بگذار

  1. ابتدا از مخزن فعلی سایت یک نسخه پشتیبان بگیر.
  2. فایل ZIP را از حالت فشرده خارج کن. محتویات آن را در همان پوشه‌ای قرار بده که index.html سایت فعلی داخل آن است. خود ZIP را آپلود نکن.
  3. در سایت گیت‌هاب از Add file → Upload files استفاده کن. فایل‌ها و پوشه‌ها را با همان ساختار بکش و رها کن؛ سپس Commit changes را بزن.
  4. فایل CNAME، دامنه شخصی، تنظیمات Pages و فایل‌های دیگر مخزن را حذف یا تغییر نده. این بسته دامنه را تنظیم نمی‌کند.
  5. بعد از انتشار، آدرس https://YOUR-DOMAIN/admin/ را باز کن. اگر سایت داخل زیردایرکتوری است، admin/ را به آدرس همان سایت اضافه کن.

اگر نسخه آنلاین از زمان ارسال ZIP تغییر کرده، قبل از جایگزینی index.html باید تغییرات دو نسخه با هم ادغام شوند.

۲. ورود مدیر را به گیت‌هاب وصل کن

این نسخه با کلید دسترسی محدود گیت‌هاب کار می‌کند؛ ورود با نام کاربری و رمز جداگانه ندارد. خود صفحه پنل عمومی است، اما ذخیره تغییرات فقط با کلید مجاز گیت‌هاب ممکن می‌شود.

  1. در گیت‌هاب به Settings → Developer settings → Personal access tokens → Fine-grained tokens برو؛ صفحه کلیدهای دسترسی.
  2. Generate new token را بزن. نامی مثل Portfolio admin بده و تاریخ انقضا تعیین کن.
  3. در Repository access گزینه Only select repositories و فقط مخزن همین سایت را انتخاب کن.
  4. در Repository permissions فقط Contents: Read and write را فعال کن. Metadata به‌صورت خودکار خواندنی است. به دسترسی کامل حساب نیاز نیست.
  5. کلید ساخته‌شده را در بخش «اتصال به گیت‌هاب» پنل وارد کن؛ نام حساب، مخزن، شاخه انتشار (معمولاً main) و پوشه سایت را هم بنویس. پوشه را برای سایت ریشه خالی بگذار؛ اگر Pages از docs منتشر می‌شود، بنویس docs.
  6. «اتصال و خواندن اطلاعات» را بزن. فایل‌های نسخه جدید باید قبلاً روی همان شاخه بارگذاری شده باشند.

کلید را در چت، کد سایت یا فایل تنظیمات نگذار. پنل کلید را فقط در حافظه همین صفحه نگه می‌دارد و فقط برای GitHub API استفاده می‌کند. بعد از بارگذاری دوباره صفحه کلید را مجدداً وارد می‌کنی. برای لغو دسترسی می‌توانی کلید را از گیت‌هاب حذف کنی.

اگر شاخه محافظت شده باشد یا اجازه ثبت مستقیم نداشته باشی، انتشار مستقیم از این پنل انجام نمی‌شود؛ قوانین مخزن را برای دورزدن محدودیت‌ها تغییر نده.

۳. پروژه و عکس را مدیریت کن

  • پروژه جدید: عنوان، دسته، توضیح و کاور را وارد کن. برای ویدیو لینک YouTube، youtu.be، Shorts یا Live معتبر وارد کن.
  • کاور و عکس‌های تکمیلی: عکس را در بخش عکس‌ها آپلود کن. مسیر آن را می‌توانی برای کاور یا عکس‌های تکمیلی کپی کنی. هر عکس حداکثر ۸ مگابایت است.
  • هدر: در تنظیمات، ویدیوی MP4 یا WebM تا ۲۰ مگابایت را انتخاب کن. حداکثر مجموع فایل‌های هر نوبت انتشار ۴۰ مگابایت است.
  • ذخیره پروژه: ابتدا در ویرایش فعلی ذخیره می‌شود. برای اعمال در سایت حتماً «انتشار تغییرات» را بزن و تا پایان صبر کن. تا فایل‌های جدید منتشر نشده‌اند، صفحه را نبند.
  • حذف: پروژه به سطل زباله می‌رود و قابل بازیابی است. عکس استفاده‌شده در پروژه یا سطل زباله حذف نمی‌شود؛ ابتدا ارجاعش را تغییر بده.
  • پیش‌نویس: در سایت نمایش داده نمی‌شود؛ اما در مخزن عمومی، فایل اطلاعات و تاریخچه گیت قابل خواندن هستند. اطلاعات محرمانه وارد نکن.
  • پشتیبان: دکمه پشتیبان، اطلاعات JSON را دانلود می‌کند؛ شامل خود عکس‌ها یا ویدیو نیست. برای پشتیبان کامل از مخزن هم نسخه بگیر. بازیابی دستی اطلاعات باید همراه با تولید دوباره content.js باشد.

اگر شخص دیگری یا خودت خارج از پنل مخزن را تغییر بدهی، پنل انتشار را متوقف می‌کند تا تغییراتش پاک نشوند. در این حالت پشتیبان بگیر، دوباره متصل شو و ویرایش موردنظر را روی نسخه تازه اعمال کن.

۴. آمار واقعی را فعال کن

  1. در Google Analytics با حساب خودت یک GA4 Property و جریان وب (Web data stream) برای دامنه سایت بساز.
  2. شناسه Measurement ID که با G- شروع می‌شود را در تنظیمات پنل وارد کن. شماره عددی Property اختیاری است و دکمه گزارش را مستقیماً به گزارش آن حساب می‌برد.
  3. تنظیمات را ذخیره کن و «انتشار تغییرات» را بزن.
  4. سایت عمومی را باز کن و به آمارگیری اجازه بده. بعد از آن، گزارش Realtime را در حساب خودت بررسی کن. گزارش‌های دیگر ممکن است با تأخیر آماده شوند.

بخش آمار پنل، گزارش خصوصی گوگل را باز می‌کند؛ اعداد را داخل پنل کپی یا جعل نمی‌کند. روز/هفته/ماه و منبع ورود را در همان گزارش می‌بینی. آمار قدیمی قابل بازسازی نیست و کاربرانی که اجازه ندهند، مسدودکننده داشته باشند یا نتوانند به گوگل متصل شوند ممکن است ثبت نشوند. منبع ورود همه کاربران قابل تشخیص نیست.

رویدادها: view_project با project_id، view_category با category_id، و contact_click با channel. برای گزارش تفکیکی این پارامترها، در GA4 برایشان Custom dimension با دامنه Event تعریف کن. هیچ متن فرم یا ایمیلی در پارامترهای رویداد ارسال نمی‌شود.

آمارگیری قبل از اجازه بازدیدکننده اجرا نمی‌شود. انتخاب او از پایین صفحه با «Analytics preferences» قابل تغییر است.

چه چیزی تغییر کرده؟

ظاهر، چیدمان، انیمیشن‌های سه‌بعدی و فایل‌های گرافیکی اصلی حفظ شده‌اند. فقط اتصال داده پروژه‌ها و تنظیمات، پخش یوتیوب و اسکریپت اتصال آمار اضافه شده‌اند. پنل فارسی در پوشه admin مستقل است. فرم تماس موجود همچنان برنامه ایمیل مخاطب را باز می‌کند؛ صندوق دریافت پیام سروری اضافه نشده است.

سایت اطلاعات را از data/content.js می‌خواند. پنل فایل قابل‌ویرایش data/content.json را مدیریت می‌کند و هر دو فایل را همراه با عکس‌ها در یک ثبت گیت‌هاب به‌روزرسانی می‌کند. چهار دسته اصلی ثابت هستند تا انیمیشن‌های موجود حفظ شوند.
